# 王尔德人脉网络浏览器

自0.1.74起，运行DLL将原生人脉网络调整为固定窗口：左侧显示原生详情与解锁按钮，右侧显示分类标签、搜索、筛选和网格。右侧竖向滚动条始终显示；不足一页时滑块占满轨道，超过一页后可拖动或用滚轮浏览。分类过多时，顶部分类栏单独横向滚动。

玩家只需正常安装同一份 `Mods/EZapi.dll`。此功能不需要额外插件，也不要求启用开发者工具。

## 其他 Mod 的接入约定

没有写死原版六类或条目 ID。打开窗口后，每 0.35 秒仅扫描该窗口内的 `NetworkElement`。正常追加到原生分类行的条目自动进入相同标签；新增分类容器也会被发现。容器原有标题优先按相邻布局识别，找不到时使用升级的本地化副标题或容器名。原分类容器保留，条目在窗口打开期间移入其滚动内容子节点。

请遵循这些规则：

- 为真实条目设置稳定、唯一的 `id`，保留合法原生 `Button.onClick` 及悬停/按下事件。
- 新条目放在原版窗口或其分类容器下面；不要把调试模板设为 active。EZapi 不激活原本禁用的模板。
- 新类别使用独立 `RectTransform` 容器。原版结构中，标题是容器附近的同级 TMP 文本；也可让条目的原生升级提供准确本地化副标题。
- 每次打开时重新解析对象。不要跨读档缓存 Unity 对象，也不要假定条目始终是原分类的直接子节点；通过 `GetComponentsInChildren<NetworkElement>(true)` 查询。
- 不要把第二份 EZapi 或游戏程序集随自己的 Mod 分发。

显示适配保留已有卡片对象及回调，最终解锁、扣费、前置条件、冷却、试玩版限制和存档仍由原游戏/原 Mod 处理。搜索同时支持名称、副标题及 ID，多词按全部匹配。筛选为全部、已购买、可负担；可负担按原生 `GetCost()` 和当前信用点判断，不表示满足前置条件或允许购买。私有费用无法读取的条目保留在“全部”，不会猜测其可负担状态。

自建私有 Canvas、没有 `NetworkElement` 的独立服务按钮、另一个完全替换人脉窗口的 Mod，无法仅凭名称自动转换；这类实现需要共同约定适配入口。此限制不影响已按原版人脉网络方式添加的条目。已有搜打撤黑客条目已在本次 UI 中出现。

## 生命周期与排错

自 0.1.77 起，首次布局在 `OpenUI(bool)` 的末尾后置回调中同步完成，普通 Mod 后置回调追加的条目会一起读取；不再等待下一次 OnUpdate。后续 0.35 秒扫描仍用于迟到的扩展。`wildBrowser.opening` 记录打开帧、绑定帧、触发来源和是否在同次打开调用内绑定。

快速直接调用 CloseUI/OpenUI 的内部脚本出现过 CanvasGroup 回退警告，该脚本不算真实关闭按钮路径验收。当前仅确认首次打开效果，后续生命周期范围见统一状态。

精确检查并安装 `WildUIManager.OpenUI(bool)` 与 `CloseUI()` 的独立补丁组 `ezapi.presentation.wild-browser`，原方法始终执行。关窗、再次打开、换场景或退出框架时，反向恢复原生父节点、顺序、RectTransform 和组件状态，撤销自有回调，再销毁自有 UI。遇到不支持结构或异常则还原原窗口并记录 `EZAPI_WILD_BROWSER`。本适配器不请求保存。

可选开发者面板中的“人脉滚动压力检查”会临时添加一个类别和 84 个原生 UI 副本，不向存档的升级目录注册；关闭人脉窗口清除。仅用于查看大量卡片的滚动/裁切，副本沿用原生条目 ID，不是实际新内容，也不应用它们重复测试购买。

诊断中的 `wildBrowser` 提供补丁就绪、分类/条目数量、搜索/筛选、选择和竖向滚动范围。完整当前验收仍以 [release-status.json](release-status.json) 为准；局部 UI 反馈不代表保存重载或所有 Mod 组合已通过。
