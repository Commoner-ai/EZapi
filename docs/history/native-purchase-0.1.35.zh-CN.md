# EZapi 0.1.35 周目购买事务验收

本版新增 `RunPurchaseApi.Purchase` 两个重载，使用当前周目的原生现金接口，组合最多 128 个同步交付步骤。付款、交付、逆序恢复和退款分别核对结果；交付恢复失败或现金出现不明变化时返回 `RecoveryFailed`，避免误退款或报告成功。用法见 [周目购买指南](../run-purchase.zh-CN.md) 和 `../src/EZapi.Sample/RunPurchaseExamples.cs`。EZapi 不引用、加载、转发或分发 Forge。

最终新进程仅加载 EZapi.dll，载入测试档 532，购买专项 **79 项通过、0 失败**。覆盖余额不足、预检拒绝、付款交付成功、零费用、部分完成、交付抛错、付款后资格改变、恢复返回 false、现金干扰、嵌套购买和纯付款。成功案例原生现金从 550 扣至 543，同一原生物品实际从临时来源库存进入临时目标库存。所有测试案例结束后真实现金回到 550，临时物品和库存已由夹具清理；测试不向玩家主库存发放商品、不主动保存。

恢复 false 和现金干扰是主动故障注入。产品接口记录 RecoveryFailed 时没有自动退款；测试夹具在记录完整结果后，单独核对当前周目和确切测试差额，再清理自身物品和现金。夹具结束时恢复 550 不能用来声称产品在不确定业务状态下会自动退款。

最终证据在发行包 `verification/native/verified/`，工作区来源为 `work/native-0.1.35-run-purchase-20261020/verified/`。本轮新进程只执行购买专项 79 项；0.1.34 的 949 项实机结果属于其冻结版本，不能相加为 0.1.35 的 1,028 项实机。载入、调试检查、导出、返回菜单和正常退出均有操作或日志证据；返回菜单后的旧购买报告是历史快照，不代表再次执行。

离线 **20 套、5,190 项通过**，其中购买专项 74 项直接链接产品 RunPurchase.cs、Transactions.cs，原生 PlayerStore 和会话边界使用替身。覆盖原生扣款异常与部分扣款、错误余额、交付恢复失败、周目切换、store 身份、重入、步骤容量等。购买 74、对话 1,436、阅读 139 另在 .NET 8 复跑通过，重复运行不重复计数。

三个项目 Release 构建 0 警告、0 错误；505 个直接游戏方法引用完整签名匹配；Unity 94 个直接引用、99 个可达方法没有 unstripping 空壳。无自动 SaveGame、自动 HarmonyPatch 特性或手工 Tooltip.Build。购买本身不增加全局资金钩子。实机日志无 ERROR，唯一 WARNING 为加载器既有 Class::Init 提示。

本轮测试前记录的 534 个 `.es3` 存档 SHA256 均保持不变；发行包不含存档。旧版 0.1.34 冻结 ZIP 保持原 SHA。发行 DLL、安装 DLL、实测 DLL 和源码构建产物由专项验收器核对一致；ZIP 条目唯一、CRC 和各 payload/manifest SHA256 实读核验。

边界：购买是同步补偿事务，不提供自动保存、跨夜补偿、异步/网络/跨进程原子性、崩溃恢复或持久幂等。作者 Check 必须只读，Apply/Restore 必须核对自己的业务写入。真实第三方补丁组合、联机大厅/搜打撤组合未验收。当前 Forge 覆盖仍为 **39 组：21 implemented、13 partial、5 missing**，完整目标继续。
