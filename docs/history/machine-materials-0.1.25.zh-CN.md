# 0.1.25 标准材料事务验收

本版在050rev5-L游戏构建中，用独立EZapi.dll和既有可丢弃测试档527运行。操作由`Invoke-EZapiNativeTest.ps1`合并重放，保存截图、输入日志、逐场景资源快照及最终诊断。不发放临时机器或材料，不请求保存。

最终二进制验收：109材料/标准事务检查、118配方检查、52加工/倒液检查、46布局检查、48工厂检查、14模块检查、12物品检查，共399通过、0失败。8套离线检查共972通过；离线配方套件仅验自定义分支，默认事务替身会立即抛错，默认消费证据来自游戏内检查。

材料从原生堆5取2后剩3；失败原生合回原堆5并恢复原坐标、状态和值。整堆转出后能原位退回；确认后通过Expel/Destroy消费。输出拒绝、交付第1件后第2件被拒绝、保管第1份材料后第2份被拒绝都成功恢复。原生输出准入回调期间，同组材料与电池无法被额外移除。

成功批次电100→93、水500000→499000parts；失败恢复100及500000。每件新液体产物真实填充1000parts并保存声明的价值8、品质依据3。通知异常仍Committed、CompletionError且只调用一次。输出满在Apply前拒绝；没有物品材料的液体/电力批次也通过。

原生AddLiquid负数观察前后液体完全相同，因此指定成分默认消费在创建产品/写资源前拒绝。包含内部物品的材料也要求自定义Transaction，防止默认消费连带丢失内容物。

三个项目0警告0错误；373直接游戏接口完整签名匹配；88直接Unity引用/93可达方法，无unstripping空壳。无Forge引用、自动SaveGame、自动HarmonyPatch属性或手动tooltip Build。冻结最终0物品/0句柄，permitActive=false，准入句柄与临时配方目录清空。

只读核对524历史文件及527存档SHA256不变；玩家拥有量、测试计数和三瓶液体基线不变。最终日志无ERROR，两条WARNING分别是加载器Class::Init替代和主动null工厂测试的预期拒绝。

完整证据在发布包verification/native与verification.json，含最终DLL哈希；初始候选和中间保护补强前的日志不作为最终DLL验收。旧0.1.24包保持冻结。

本版未验收正常机器保存重载、跨夜、外部电力、联机或搜打撤兼容、全部混合液反应副作用；未实现机器模板统一注册、配方JSON导入或完整Forge公共API。Forge39组仍15实现/11部分/13缺失，完整目标继续进行。
