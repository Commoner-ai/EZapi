# EZapi 的目标与开发顺序

EZapi 是 Probably Stolen 的独立 Mod 前置。最终目标是让作者和 AI 通过清楚的 JSON、少量 DLL 调用和完整模板，做出稳定、互相兼容的 Mod。

2026-10-20 用户确认当前顺序：先重视功能覆盖、底层可靠性和强兼容性，再持续补充 EZ 易用层。易用目标没有取消；不能用公共接口数量代替作者使用体验。

Forge 0.6.36 是最低功能参照。我们读取其公共接口及部分实现用于理解能力和故障边界，框架自身独立实现，不引用、加载或分发 Forge。覆盖一种功能不要求复制同名接口、参数或内部架构。当前底层高级接口比较详细，这不代表最终推荐入口已经足够简单。

## 三个独立验收维度

| 维度 | 判断依据 | 不足时如何报告 |
| --- | --- | --- |
| 功能覆盖 | 原生行为、回调、状态和释放契约能否完成目标 | implemented / partial / missing，注明边界 |
| 可靠性与兼容性 | 官方入口、精确签名、作用域隔离、资源核对、失败恢复、生命周期清理，以及真实运行证据 | 编译、安装、玩法、保存重载、组合测试分别记录 |
| EZ 易用性 | 普通需求的默认值、完整示例、字段索引、明确错误与修复路径，作者是否需要理解 IL2CPP 内部细节 | 只评价实际可用的入口；尚未用 DeepSeek 实测时不得声称其已验证 |

## 接口设计要求

普通物品优先 JSON；需要运行逻辑时提供可编译 C# 示例。复杂机器及外电保留高级扩展能力，后续围绕常见需求提供安全默认和简单模板。不要让普通内容作者自行安装Harmony、找原生偏移、维护跨场景指针或实现通用材料回滚。

每项 API 说明初始化/目录/周目时机、单位、默认值、限制、所有权、释放方式和失败结果。JSON schema、源码注释、最小完整示例、API/错误/源码索引必须一致。状态输出 JSON 与可执行配置应明确区分。

优先官方已提供的功能。确需补丁时匹配完整目标签名，限制到本功能拥有的对象；不能覆盖其它 Mod 的注册或对全局拖放设置临时豁免。签名不符时关闭对应能力并报错。精确匹配能防止误用，但不意味着未经验证的所有游戏版本或 Mod 组合均兼容。

## 当前诚实状态

物品、标签、提示、内容包已有 JSON 与示例。机器、配方、自动化和外电已建立底层功能与部分实机证据，日常高级接入仍需简化。先按已确认的优先级补齐能力和可靠性，之后以常见开发任务评估是否真正 EZ。
