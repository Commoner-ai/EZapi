# 0.1.28 共享制造终端验收

本版新增 EZapi 自有共享终端、多作者配方贡献和首作者加价配置，复用已有机器布局、准入、图鉴、标准事务与夜间调度。工厂通过当前官方 MachineryHelper/ModuleHelper 建立真实机器状态；终端使用自己的内嵌PNG，不依赖 Forge DLL 或资源。开发契约见[共享终端指南](manufacturing-terminal.zh-CN.md)。

- 11套共1,347项离线检查全部通过：新增终端配置77，自动化217、统一注册81、配方406、事务55、倒液97、图鉴101、服务60、生产93、库存保护97、内容包63。目录/原生替身的边界在各报告明确标注。
- 最终DLL合并644项实机检查全部通过：新增终端84，原有自动化119、统一注册42、材料109、配方118、事务52、布局46、工厂48、模块14、原生物品12。两作者配方均实际加工；0/15/25/1000%加价使100价值投入产出100/115/125/1100。50%效率模块使真实扣电25降至13。缺料、缺电、满产物槽均保持资源。
- 独立531测试档，两台机器分别放入2份和1份材料、各100电。第一晚各产1件、各余75电；正常重启载入后投入、价格、电量、夜次和实例ID均保留，输入/输出/窗口指针重新创建且彼此独立。
- 第二晚第一台累计2件、余50电，空机仍为1件、余75电；再次重启载入第3天保持相同结果。配置首作者随进程清除，默认15%；内容作者在初始化重新提交配置。测试配方由显式夹具按钮在重载后重新贡献，对应正式内容Mod初始化注册。
- 正常UI打开两个终端窗口、拖动窗口和移动机器均有截图/输入journal。新增按钮与物品说明的重叠已修复。终端窗口尺寸由原生布局管理，可拖动到屏幕内。
- 374个直接游戏方法完整签名匹配；Unity直接88/可达93个包装调用没有反剥离空壳。三项目构建0警告0错误。50条真实批次结果、5条事务结果、终端状态样例通过JSON schema检查，并拒绝4个无效结果样例。

最终证据为 `verification/native/final`、`final-reload`、`final-day3-reload`，对应同一最终DLL。早期candidate/night仅为UI改动前的调查，不计入本包实机验收。最终日志无ERROR；主回归4条WARNING分别来自加载器兼容提示和主动触发的Before/After异常、null工厂拒绝。

只加载EZapi.dll，正常游戏UI过夜保存，不调用自动SaveGame；524份历史文件及527基准档哈希保持不变。发布包没有玩家.es3存档。哈希、源码/测试输入与日志见verification.json及checksums.json。

完整Forge目标继续active，当前仍16组实现、12组部分、11组缺失。Registration组的共享加价成员已实现，整组仍保守保留partial，尚有完整模板/资源契约边界。外部电力、指定成分默认扣液、含内装物材料、专用液体产物槽、特殊图解码和其余缺失API继续开发。该验收不代表联机大厅/搜打撤组合兼容或崩溃持久补偿已通过。
