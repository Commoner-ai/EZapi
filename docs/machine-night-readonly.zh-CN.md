# 夜间批次数回调的只读契约

`MachineDefinition.ResolveNightlyBatchCount` 只负责返回本晚允许尝试的批次数，不应修改机器、材料、槽位或存档。省略时为1；有效范围1..64。禁用自动夜间加工用 `EnableNightly=false`，不要用返回0代替。

```csharp
// 示例为MachineDefinition的属性赋值；只读取已有标签，不使用GetTag创建标签。
ResolveNightlyBatchCount = machine => machine.IsTag("AUTHOR_FAST_MODE") ? 2 : 1;
```

调度器每批前重新解析；后续返回较小配额会提前停止，增大配额不会超过本晚第一次的上限。任何一批失败都停止本台机器本晚的循环。手动 `ProcessBatch` 始终只尝试一批，不调用这个夜间回调。

0.1.68在回调前捕获完整机器物品图。检查根和后代的身份、数量、所有权、形状、父库存、状态/字典身份、全部标签、基础价值、子窗口、图连接与库存锁；同时保留槽位绑定、电量和液体的原有检查。回调后重新取得槽位，任一变化都停止加工并报告 `nightly count resolver changed resources`。单个没有内装物的物品也必须检查标签，不能因数量不变就认为没有修改。

完整图沿用既有边界：最多4096物品、8192节点/边、16384个合计标签，每个物品最多4096标签。超限或非法图在回调前拒绝。本检查仅同步运行，原生引用不跨回调保存；不是异步事务或崩溃恢复机制。

本晚尝试标记在作者回调之前写入机器状态。失败和同晚重复事件不会追加生产，标记随游戏正常保存持久化；框架不会自动保存。只读审计负责发现变化并阻止后续生产，**不负责撤销作者直接写入的任意状态**。需要修改材料的玩法应在配方事务内实现。不要在回调里Destroy物品、切换场景、读档或写库存。
