# 外部电力：EZapi 0.1.30

`ExternalPowerApi`让内容Mod将连接器物品放入EZapi机器的电池槽，机器通过作者的`IPowerTransaction`操作外部电源。框架负责配方、材料预留、产物交付及失败调用顺序；作者负责真实外部能源的预检、扣除、校验、恢复。可编译示例见`src/EZapi.Sample/ExternalPowerExamples.cs`。

## 最小接入顺序

1. 使用自己的命名空间注册连接器物品，例如`author.power.connector`。推荐复制示例`RegisterConnectorItem`，在每次物品工厂创建的新游离、未拥有单件上调用`ExternalPowerApi.InitializeConnector(item)`。它通过官方Init/Set建立原生电源准入标签与零内部电量，使用精确实例的同步许可；不会开放充电。提供方须先登记，工厂只在原生目录就绪后由游戏调用。
2. EZapi初始化完成后，在主线程调用`ExternalPowerApi.Register(ownerId,itemId,energy,plan)`，保存`IDisposable`句柄。登记可以早于目录就绪；此时`IsAvailable=false`，不能据此认为登记失败。停用内容Mod时释放句柄。
3. `energy(connector)`每次只读查找当前真实电源。负数表示未连接，0表示已连接但电量不足，正数单位为原生整数能源。不能递归查询自身连接器；框架拒绝重入、隔离异常，公开`GetEnergy`在断开或失败时返回0。`IsConnected`可区分断开与空电源。
4. `plan(machine,connector,amount)`只创建本次计划，不能修改资源或提前扣电。返回一个新的`IPowerTransaction`。不要缓存跨场景物品、库存或事务对象；用当前周目身份和实例身份判断有效性。
5. 用常规`MachineRegistrationApi`或`MachineRecipeApi.CreateBatchProcessor`登记配方；标准事务会识别连接器。此版本自定义`MachineRecipe.Transaction`仍由作者负责外电事务，不能在其中直接调用原生Draw冒充可恢复扣电。

## 连接器标签要求

连接器必须满足原生电池槽的准入，而`Register`本身不创建物品、标签、图标或电网。`InitializeConnector`只接受已登记、未拥有、游离、无子窗口、未初始化的新单件；创建或读档工厂均先创建独立实例再调用它。它不要求周目已经载入，但原生钩子必须就绪。初始化写入标记后若原生调用失败，作者必须销毁整个未交付实例，不能重试部分初始化对象。普通Init/Set/Charge仍被拦截；禁止对已拥有或已进入库存的连接器再次初始化。示例提供方与物品工厂两部分均可编译；真实保存恢复需另行验收。

## 事务契约

| 方法 | 责任 |
| --- | --- |
| `Validate()` | 只读核对原电量、身份、权限及电源资格。框架可能调用多次。 |
| `Debit()` | 每个实际正耗电批次至多调用一次；允许失败抛异常，作者仍要支持部分写入后的恢复。 |
| `Verify()` | 只读核对真实能源与计划。框架另核对查询值等于批次前电量减实际电耗。 |
| `Restore()` | 恢复原来真实电源，必须幂等；即使Debit抛异常也可能被调用。返回true仅表示作者恢复完成，框架仍读回。 |
| `Fault(reason)` | 恢复无法确认时记录故障或隔离，不补发、不再次扣电、不自动重试。 |

零电耗仍要求连接器在线，但不创建提供方事务。输出空间不足或材料不足时不扣电；提供方Validate拒绝时不调用Debit。Debit之后发生任何资源或产物交付失败，都调用原提供方Restore。释放登记后不能开启新计划；已经扣电的计划仍保留原提供方委托用于恢复，不能换一个新提供方冒充退款。

外部电源可能处于机器冻结图之外；作者必须自行保证它在同步事务内不会被其它回调并发修改，并拒绝不确定身份。只读查询、plan、Validate、Verify必须无副作用。框架无法恢复违反只读约定的任意外部状态，也不提供网络事务、跨帧事务、崩溃恢复或自动保存。

## 原生边界

完整匹配并安装十二个必需钩子（十个PowerHelper、一个熔炉委托、一个原实例Destroy）后`IsAvailable`为true；安装失败、钩子所有者丢失则查询失败关闭。`HookApi.GetRuntimeStatus()`与diagnostics的`externalPower.native`可读完整目标和错误。精确identifier匹配，不跟随fake ID、别名或标签。最多128个活动提供方，一个ID只能一个活动句柄；同步提供方回调或在途电力事务内不得新增登记。

原生GetAvailableEnergy/CanDraw转向提供方；连接器拒绝ChargeBattery两个重载、InitPowerSourceItem、SetPowerSourceAt及TryRemoveEnergy，IsPowerSourceFull为true。tooltip显示连接状态及外部可用电量，不手动Build。冻结的普通电池也不能充电；未登记物品沿用原生行为。

原版熔炉已通过当前构建的精确同步加工委托接入外电。只处理安装已登记连接器的熔炉；普通电池沿用原版算法。捕获输入、旧输出、机器/模块状态和真实能源日记，延后本批原物料的销毁。失败先调用原提供方恢复，再清新产物、逐原实例退回原槽，并核对数量、身份、标签、价值、形状和位置。即使某个恢复步骤失败，其余步骤仍尝试；不能确认恢复时隔离机器。

资源结算和恢复在一次原生回调内完成。Unity的Destroy到帧末才完成，不能同帧要求IsDestroyed=true。框架立即核对对象已脱离库存，两帧后核对销毁；最多128个待清理批次，同一机器清理完成前不能再执行。销毁确认失败只隔离，不对已提交批次退款/重试。读档换周目或停止时不访问过期队列对象。这是销毁检查，不提供跨帧资源事务。

0.1.67已支持子窗口材料的显式ConsumeGraph与旧输出子图保留：旧四参数Register默认拒绝子窗口输入，第五参数可显式允许整图消耗；旧输出子图始终保留。总原输入/旧输出最多128根、图物品合计4096、模块128。EZapi外电跨夜/冷启动已在0.1.62验证；本轮原版熔炉只验证同步临时图，不声称全部跨夜组合或崩溃恢复。没有精确熔炉上下文的正耗电Draw仍拒绝。`Power.TryDebit`对连接器返回Rejected；自定义事务仍由作者对接完整外电责任。

验收与官方原生行为差异见 `native-furnace-power-0.1.30.zh-CN.md`。

## 检查

游戏调试面板“外部电力检查”集中执行临时图回归，随后导出diagnostics。它在另一个临时机器内放真实原生电池，不是整数替身；检查实际扣电、材料/产物、异常/拒绝/释放后的恢复，以及原生查询和防充电。不会发放或保存测试图。离线测试链接真实登记和电力日记，但原生身份与钩子是替身，不能代替实机。
