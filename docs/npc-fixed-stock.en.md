# Fixed merchant slots and machine stock (0.1.64)

Use existing NativeItemOptions.NpcTrade or JSON npcTrade, after catalog application. A functional custom machine sets MachineDefinition.ItemOptions.NpcTrade during RegisterMachine; a JSON category alone does not add machine behavior. Content packs require minEzapiVersion 0.1.64.

Fixed native slots generated by inventor night/visiting shops and thief/petty-thief/food-thief callbacks now use the current item's official type. Classification precedence: MACHINE, MODULE, ORE, FOOD, MEDICAL, MATERIAL, HOUSEHOLD_GOOD, HOUSEHOLD. Unclassified special goods, including keys, remain unchanged. No classification is inferred from translated names or guessed IDs.

Each existing native slot contributes its original item at weight1; eligible custom candidates contribute Weight. A sole custom weight2 therefore gives approximately2/3 probability within a matching slot. Native unlock/day/slot-generation rules remain in control. Supplier, IncludeInNightShop, MinimumDay and SkipWhenOwned apply. No eligible alternative means no extra RNG/event. Named-table results retain their existing table-weight behavior and are not rolled again at delivery.

Player graph identities, not the native Owned flag alone, exclude existing items: fresh native merchant goods also carry that flag. Attached objects and registered EZapi goods are preserved. Replacement factories retain the baseline's ownership flag and native placement arguments.

Synthetic fixed-slot events use ezapi.npc.inventor.fixed or ezapi.npc.thief.fixed. Clearing itemId cancels that temporary slot. Callback/factory failure retains the already-created baseline without a reroll. Retired baselines are destroyed only after the whole generation method and official Late callbacks finish; generation/run guards isolate scopes. No global loot journal, drag logic or save is written.

Native prebuilt machines initialize power before assigning their ID. External-power lookup now ignores an unassigned ID, preserving native initialization.

Evidence: 71 offline adapter checks; 47 native NPC checks using actual generation callbacks and captured sale items;923/0 across nine native groups;19/0 reading the previous persistent fixture save. Actual shelf placement, purchase and saved results remain unverified by this stage.
